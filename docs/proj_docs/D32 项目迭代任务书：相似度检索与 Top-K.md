## 二、本次功能需求

在 D32 已有向量入库能力上，实现可用的相似度检索。

1. 实现用户问题的 Query Embedding，使用与 D32 入库阶段一致的 Embedding 模型及 384 维向量空间。
2. 调用 Spring AI 1.1.8 的 VectorStore 相似度检索接口，默认返回 Top-5。
3. 返回检索片段、来源信息及相似度分数；如果当前适配器不支持分数获取，明确记录能力限制，不得伪造分数。

5. 准备至少 10 个真实业务问题，对每个问题的 Top-5 结果逐条人工标注相关或不相关。
6. 分析检索噪声、漏召回及可能原因，形成检索评估记录。

### 3. VectorStore 相似度检索

使用 Spring AI 1.1.8 对应的 VectorStore API，基于用户问题执行相似度检索。

默认：

```text

```

要求：

1. 使用实际 VectorStore 实现，不绕过现有架构重复编写数据库检索层。
2. 能够调整 Top-K，但默认值为 5。
3. 返回 Chunk 内容、文档来源和可用的 Metadata。
4. 获取适配器真实提供的相似度分数或距离信息。
5. 明确分数的定义、方向及取值语义，不混淆 cosine distance 与 similarity。
6. 如果 Spring AI 适配器没有暴露真实分数，记录具体限制，不得自行编造或使用未经验证的分数替代。
7. 处理无结果、数据库异常和 Embedding 调用失败。
